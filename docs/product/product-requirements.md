# 产品需求文档

状态：提议稿  
版本：0.1  
产品代号：Equity Atlas  
最后更新：2026-08-09

## 1. 产品愿景

为关注中国大陆、香港、美国和日本市场的个人投资者提供中文优先、证据可追溯、限制可见的股票研究工作台。系统帮助用户理解事实、变化、风险和原有投资论点是否仍然成立，不代替用户作出投资决定。

## 2. 目标与非目标

### 目标

- 使用一个稳定标的身份统一多个市场的代码和名称；
- 汇集行情、历史价格、技术指标、基本面和后续阶段的新闻事件；
- 生成结构化研究报告，每项时效事实可追溯至来源和时间；
- 保留不可变研究上下文，支持历史复现与审计；
- 允许用户维护观察列表、手工组合、持仓和投资论点；
- 在数据不足、陈旧、矛盾或供应商失败时明确降级；
- 提供中文、日文、英文界面和市场时区显示。

### 非目标

- 券商连接、委托、自动交易或资产托管；
- 保证收益、目标价格必达、确定性预测或持牌投资建议；
- 抓取或再分发未经许可的商业数据；
- 在 MVP 中完成支付、深度多 Agent、回测和全部公告源；
- 用 LLM 替代财务公式或技术指标计算。

## 3. 用户与核心场景

| 用户 | 需要 | 关键成功信号 |
| --- | --- | --- |
| 跨市场个人研究者 | 用同一流程研究 A/H/美/日股票和 ETF | 能正确识别标的并看到来源一致的报告 |
| 日本市场关注者 | 正确处理东京代码、日文名、JPY、午休和指数 | 不出现 A 股专属概念或错误交易阶段 |
| 长期投资者 | 保存论点和失效条件，观察新证据 | 报告说明论点增强、削弱或数据不足 |
| 谨慎型用户 | 理解数据质量、风险与观点分歧 | 不完整结果不伪装成高置信结论 |
| 平台运营者 | 控制配额、成本、供应商健康和滥用 | 可审计任务、模型成本和失败原因 |

### 核心用户旅程

1. 用户注册并进入个人租户。
2. 输入 `7203.T`、`hk00700`、`MU` 或 `510300` 搜索标的；歧义时选择候选。
3. 添加到观察列表，查看带来源和时间的行情及历史图表。
4. 发起基础研究；页面展示排队、取数、分析、校验阶段。
5. 阅读结构化报告、数据限制、来源和历史版本。
6. 保存投资论点；后续报告相对指定论点版本评估变化。

## 4. MVP 功能需求

### FR-01 身份与租户

- 邮箱密码注册、登录、access/refresh token 轮换、登出和会话撤销；
- 新用户创建个人租户；所有请求绑定一个已授权租户；
- OWNER、ADMIN、MEMBER、VIEWER 权限，默认最小权限；
- 密码找回可以在邮件能力具备后启用，未启用时不暴露虚假入口。

### FR-02 标的搜索与规范化

- 支持 A 股、港股、美股、日股、指数和 ETF 的需求文档示例输入；
- 返回稳定 `instrumentId`、canonical/display symbol、MIC、市场、币种、时区和多语言名称；
- 代码歧义返回排序候选及理由，不自动选择；
- 搜索结果标记主数据来源与核验时间。

### FR-03 观察列表

- 创建、重命名、删除和排序观察列表；
- 添加、删除、排序标的，禁止同列表重复；
- 所有操作强制租户隔离并记录审计所需上下文。

### FR-04 行情与历史图表

- 显示价格、涨跌、币种、市场阶段、as-of、延迟和数据质量；
- 支持日线为 MVP 基线，返回 adjusted policy 和 bar completion 状态；
- 指标至少包含 MA5/20/60/200、RSI、MACD、成交量和波动率；
- 数据缺失、陈旧或供应商回退必须呈现限制，不显示伪造的零值。

### FR-05 基础 AI 研究

- 用户选择标的并提交 BASIC 任务；请求以租户和 idempotency key 去重；
- 所有分析读取同一不可变 snapshot；
- 输出市场概况、技术趋势、基本面可用摘要、近期催化剂、风险和限制；
- 报告符合结构化 schema，数值来自确定性计算；
- 无足够数据时可返回受限报告或明确失败，不强制生成结论。

### FR-06 报告历史

- 按标的、时间、模式和状态分页查询；
- 查看报告使用的 snapshot、来源、时间、质量、workflow/model 元数据；
- 历史报告不因最新数据、名称或提示词变化而改变。

### FR-07 手工组合和持仓

- 创建以指定币种计价的组合；
- 手工添加或更新数量、平均成本和 as-of；
- 不接受券商密码或交易凭据，不生成交易订单。

## 5. 后续阶段需求

- Phase 2：新闻去重与事件、定时研究、通知、投资论点评估、用量限制和管理面板；
- Phase 3：共享快照上的深度多 Agent、牛熊研究、风险复核、EDINET/TDnet 和防未来数据回测；
- 支付只有在套餐、税务、退款、地区和合规要求确认后实施。

## 6. 报告与内容规则

- rating 只能为 POSITIVE、WATCH、NEUTRAL、RISK_INCREASED、AVOID；
- confidence 范围 0 至 1，并受数据质量上限约束；
- 时效性事实必须关联 snapshot source 和 as-of/published time；
- 报告必须包含数据质量分数、级别和 limitations；
- 观点与事实分离，未知值使用 null/缺失状态，不能以 0 代替；
- 禁止“稳赚”“保证收益”“必涨”“无风险”等确定性承诺；
- 研究结论不得转换为下单指令。

## 7. 非功能需求

| 类别 | MVP 要求 |
| --- | --- |
| 可用性 | 产品 API 月可用性目标 99.5% |
| 性能 | 非研究同步接口 p95 < 500 ms；任务接口立即返回 202 |
| 可靠性 | 幂等任务、有限重试、熔断、回退、部分结果、可恢复队列 |
| 安全 | Argon2id、token 轮换、RLS、限流、CSP、审计、秘密脱敏 |
| 隐私 | 数据最小化、导出/删除流程、分级保留、不发送无关持仓给 LLM |
| 可观测性 | 结构化日志、trace、metrics、liveness/readiness |
| 国际化 | zh-CN 默认，支持 ja-JP/en-US；数据库 UTC，市场时区展示 |
| 可访问性 | 键盘可用、语义标签、色彩非唯一信号，目标 WCAG 2.1 AA |
| 兼容性 | 当前两版 Chromium/Firefox/Safari，响应式桌面与移动端 |

## 8. 产品分析指标

- 搜索成功率与歧义选择率（按市场）；
- 基础研究成功、受限完成和失败率；
- snapshot 平均质量及低质量原因；
- 报告来源覆盖率和验证拒绝率；
- 用户从搜索到完成首份报告的时间；
- 供应商回退率、任务排队时间和单位报告成本；
- 论点评估被查看的比例（Phase 2）。

不得将短期交易收益或“预测命中率”作为误导性的首要产品指标。

## 9. MVP 验收场景

1. 输入需求文档列举的代码，规范化结果一致且重启后 ID 不变。
2. 同一任务的所有 agent/步骤引用唯一 snapshot ID。
3. 主供应商超时后按策略回退，报告显示 provider 和限制。
4. 两个租户不能读取、推断或修改对方观察列表、持仓、任务和报告。
5. 重复提交同一 idempotency key 不会创建第二个任务或重复计费。
6. 报告 schema 不合法或时效事实无来源时不能标记成功。
7. 历史任务拒绝 data cutoff 之后的数据。
8. 日本标的正确显示 Asia/Tokyo、JPY、午休阶段，不出现 A 股专属描述。
9. Docker Compose 可启动依赖与应用并通过健康检查。
10. 核心路径有自动化测试且 CI 可重复运行。

## 10. 发布门槛与待决策

发布前必须确认数据供应商的展示、缓存、衍生、再分发和 AI 输入权利；完成威胁建模、恢复演练、依赖扫描和免责声明法务复核。首批供应商、LLM 地域和数据保留选项仍是阻塞生产发布、但不阻塞使用 mock provider 的本地开发决策。
